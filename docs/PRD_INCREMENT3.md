# 听书宝（listen_book）· 增量 PRD（v1.3 局域网/手机访问模式）

> 版本：v1.3 增量 ｜ 作者：许清楚（Xu）· 产品经理 ｜ 语言：简体中文
> 范围：仅描述本次**新增/变更**，既有已定内容（导入/分章/播放器/导出/断点/书签/删除红线）不在本文重复，详见 `PRD.md` / `ARCHITECTURE.md` / `PRD_INCREMENT.md` / `PRD_INCREMENT2.md` 及其架构文档。
> 背景：后端运行于用户本机，需暴露到局域网，让同 WiFi 的 iPhone 经电脑局域网 IP（如 `192.168.x.x:8000`）用浏览器访问网页。

## 1. 增量目标

让运行在本人电脑上的听书宝暴露到局域网，使同 WiFi 的 iPhone 可通过浏览器扫码访问，并提供可选访问口令做轻量防护。

## 2. 用户故事

1. **作为手机听书用户**，我想在 iPhone 上用浏览器打开电脑上的听书宝，这样躺在床上也能听已经生成好的电子书，不必守着电脑。
2. **作为设置者**，我想在电脑或手机上看到一个二维码，用相机/微信扫一下就跳到网页，免去手写 IP 地址的麻烦。
3. **作为在意安全的用户**，我想在把服务暴露到局域网时设一个简单口令，这样同 WiFi 的他人或嗅探不能直接调用接口翻看书架、导入或删除我的 app 数据。

## 3. 增量需求池

> 标注：🔧 后端依赖（Python/FastAPI）｜🎨 前端依赖（React/MUI）｜🛠 运维/脚本

### P0 — 核心（缺失则手机访问不可用）

| 编号 | 描述 | 依赖 | 验收标准 |
| --- | --- | --- | --- |
| LAN-001 | 后端绑定 `0.0.0.0`：监听所有网卡（经环境变量 `LISTENBOOK_HOST` 可覆盖回 `127.0.0.1`）；`localhost` 访问不受影响 | 🔧 | 设 `0.0.0.0` 后本机 `http://localhost:8000` 与 `http://127.0.0.1:8000` 仍可正常打开；未设 env 时默认即 `0.0.0.0`，满足开箱即手机可访问 |
| LAN-002 | 网络访问信息端点 `GET /api/network/info`：返回 `{ lan_ip, port, access_url }`，`lan_ip` 取首个非回环 IPv4，`port` 取运行端口，`access_url = "http://<lan_ip>:<port>"` | 🔧 | 返回合法 JSON；`lan_ip` 为局域网可达 IPv4（非 127/0.0.0.0）；`port` 与 `uvicorn` 实际端口一致；`access_url` 拼接正确 |
| LAN-003 | 二维码生成与正确性：访问信息面板据 `access_url` 生成二维码，内容为 `http://<IP>:<PORT>` | 🎨🔧 | 扫码得到的 URL 可直接在手机浏览器打开网页；二维码内容与端点返回的 `access_url` 完全一致；IP/端口变化时二维码同步刷新 |
| LAN-004 | 前端网络信息面板：入口（如 AppBar「手机访问」按钮→对话框）展示局域网 IP、端口、二维码（LAN-003）及口令输入区 | 🎨 | 面板正确显示 IP 与可扫二维码；点击入口即可弹出；口令输入后可保存并提示后续自动携带 |
| LAN-005 | 可选访问口令—配置不硬编码：token 经环境变量 `LISTENBOOK_TOKEN`（及/或 `run.py` 启动参数）传入；为空则不启用；代码中**不写死任何默认口令** | 🔧 | 不设置 token 时功能关闭；设置后生效；源码中无硬编码口令；可通过 env 或启动参数传入 |
| LAN-006 | 可选访问口令—校验中间件：启用时除白名单（`/api/health`、`/api/network/info`）外，所有 `/api/*` 请求须携带正确 token（支持 `Header: X-Access-Token` **或** 查询参数 `?token=`），缺失/错误返回 401/403；关闭时无需 token | 🔧 | 启用且未带 token → 401/403；带正确 token → 正常通过；关闭 token → 无需携带即可访问全部 `/api/*`；白名单端点始终免 token |
| LAN-007 | 前端自动携带口令：`localStorage` 存 token；fetch 请求自动附加 `X-Access-Token`；音频流 `<audio src>` 与导出下载 `<a download>` 的 URL 追加 `?token=`（因这类浏览器原生请求无法带自定义 Header） | 🎨 | 首次输入一次后，后续请求自动带 token；刷新页面仍有效；清除存储后可重新输入；媒体/导出地址正确附加 token 并可用 |

### 关联说明（非独立条目）

- **CORS 不变**：运行态前端与 API 同源（`BASE_URL='/api'`），`<audio>/<a download>` 与 fetch 均发往同一 `host:port`，不触发跨域，无需调整 `allow_origins`。
- **静态站点根 `/` 保持开放**：手机需先加载 SPA 才能输入口令，故仅 `/api/*`（除白名单）受 token 保护，根路径静态资源不拦截。
- **口令覆盖媒体/导出**：`/api/books/{id}/chapters/{idx}/audio`、`/api/books/{id}/audio`、`/api/books/{id}/export` 等同属 `/api/*`，必须同时支持 Header 与 `?token=` 两种携带方式（LAN-006/007 已含）。

## 4. 安全与边界说明

- **仅限信任局域网**：`0.0.0.0` 会使服务暴露到所有网卡，仅应在可信 WiFi 下使用；在公共网络/开放端口场景下，任意同网设备均可尝试访问。
- **口令为轻量防护，非强加密**：它只是一道"随手设防"，不构建账号体系、不做速率限制/防爆破；HTTP 明文传输下，同网抓包即可获取 token，不能抵御有意的逆向或重放。
- **HTTPS 暂不在范围（P2）**：全程 HTTP 明文，token 同样明文；本期不处理证书与加密通道。
- **本模式不涉及任何用户文件改动**：仅调整网络绑定、新增"读取网卡信息/渲染二维码/校验 token"逻辑，**不读写** `data/` 内音频/文本/元数据，**更不触碰**用户原始 txt/epub/pdf。

## 5. 对既有红线的重申

- **红线本质不变**：`original_path` 仅记录，后端任何路径（import/delete/retry/导出/续听）**绝不读/写/删/移动**用户原始 txt/epub/pdf。
- **本增量零文件读写**：不新增对用户文件或 `data/` 内既有数据的任何写操作；网络信息仅"读取网卡地址"、口令仅做"请求校验"、二维码仅做"图像渲染"，三者均不产生持久化副作用。
- **既有能力行为一致**：删除（仅清 app 数据）、导出（合并分章副本）、断点/书签在 LAN 模式下与本地完全一致，红线不受影响。

## 6. 待确认 / 风险

1. **局域网 IP 获取可靠性**：多网卡（有线+无线+VPN+Docker 桥接）下"首个非回环 IPv4"可能取到手机不可达的虚拟地址。需定调：自动优选策略 / 允许 env 指定 `LISTENBOOK_LAN_IP` / 在面板列出所有候选 IP 供用户选择。
2. **口令在前端存储的安全性**：存 `localStorage` 为明文，同设备其他应用或页面 XSS 均可读取。需确认：是否接受明文，或改用 `sessionStorage`/内存态（重启失效）、或加一层简易混淆（非加密）。
3. **二维码库选型**：前端 `qrcode`（npm，需构建、零后端依赖）vs 后端生成图片（如 `segno`/`qrcode`，返回 data URL 或 PNG 流）。需定调默认方案（倾向前端 `qrcode`，保持后端轻量；`start.sh` 终端二维码则走后端 venv Python）。
4. **关闭口令时的暴露面**：`0.0.0.0` + 无 token 时，局域网任意设备可读写书架、导入、导出、删除 app 数据（仍不碰原始文件）。需在 UI 与启动日志明确告警"未设口令 = 局域网开放"，并建议仅在信任网络使用。
5. **媒体/导出请求的 token 携带**：`<audio src>` 与 `<a download>` 无法附带自定义 Header，token 必须同时支持查询参数（`?token=`）才能覆盖音频流与导出下载。需确认该方案被采纳，否则这两类请求在启用口令后将 401。
6. **白名单范围**：`/api/health` 与 `/api/network/info` 是否免 token（setup 流程依赖——手机加载页面后需先拿到 URL 才能扫码/输入口令）。需定调，避免"设了口令却无法获取访问 URL"的死锁。

## 附：配置 / 接口变更要点（供架构参考，非用户可见）

### A. 配置常量增量（`backend/config.py`）

- `HOST` 默认值由 `"127.0.0.1"` 改为 `"0.0.0.0"`，并支持 env 覆盖：`HOST = os.getenv("LISTENBOOK_HOST", "0.0.0.0")`。
- 新增可选 env：`LISTENBOOK_PORT`（覆盖 `PORT`）、`LISTENBOOK_TOKEN`（访问口令，空=关闭）、`LISTENBOOK_LAN_IP`（显式指定局域网地址，优先于自动探测）。

### B. 新增端点

| 方法 | 路径 | 说明 | 口令 |
| --- | --- | --- | --- |
| GET | `/api/network/info` | 返回 `{ lan_ip, port, access_url }` | **免**（白名单） |
| GET | `/api/health` | 沿用，保持免 token | **免**（白名单） |

### C. 口令中间件（新增，挂载于所有 `/api/*`）

- 读取 `LISTENBOOK_TOKEN`；为空 → 跳过校验。
- 启用时，对每个 `/api/*`（白名单除外）校验 `X-Access-Token` Header 或 `?token=` 查询参数，与配置值相等则放行，否则返回 401/403。
- 静态根 `/` 与 `frontend/dist` 资源**不**经此中间件。

### D. 前端增量要点

- `api/client.js`：请求封装自动附加 `X-Access-Token`（取自 `localStorage`）；媒体/导出 URL 拼接 `?token=`。
- 新增 `NetworkPanel` 组件（AppBar「手机访问」入口 → 对话框）：展示 `lan_ip`/`port`、渲染二维码（前端 `qrcode`）、口令输入与保存。
