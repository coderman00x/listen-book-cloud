# 听书宝（listen_book）· 增量 PRD（v1.1 增强）

> 版本：v1.1 增量 ｜ 作者：许清楚（Xu）· 产品经理 ｜ 语言：简体中文
> 范围：仅描述本次**新增/变更**，既有已定内容（txt 流程、基础播放器、删除红线原则）不在本文重复，详见 `PRD.md` / `ARCHITECTURE.md`。

## 1. 增量目标

在本地网页应用「听书宝」既有 txt 听书能力之上，新增**一键启动脚本、epub/pdf 导入、分章听书**三项增强，让用户「一条命令跑起来、更多格式能导入、长书按章听」。

## 2. 用户故事

1. **作为电脑小白用户**，我想在项目目录运行一条命令就自动装好环境并打开网页，这样无需懂 venv/npm 也能立刻用听书宝。
2. **作为藏书多样的读者**，我想直接把下载的 epub/pdf 拖进听书宝，系统自动提取正文并像 txt 一样配音，这样不用先手动转成 txt。
3. **作为听长篇的用户**，我想导入后书自动分成章节，并在播放器里看到章节列表、用上章/下章和点击跳转，这样能随时回到想听的段落。
4. **作为谨慎用户**，我想无论导入 epub/pdf 还是分了章，删除都只清 app 内的音频与文本副本，绝不碰我的原始文件，这样用得安心。

## 4. 对既有红线的重申与强化

- **红线本质不变**：`original_path` 仅记录，后端任何路径（import/delete/retry/分章重新生成）**只读取用户原始文件内容用于提取文本，绝不写/删/移动/重命名**原始 epub/pdf/txt。
- **app 数据范围显式扩大**：本次新增后，app 数据 = `data/audio/<book_id>/`（所有章节 mp3 副本）+ `data/text/<book_id>.txt`（文本副本）+ `data/books.json`/`settings.json`（元数据）。删除操作必须覆盖**全部**上述项。
- **分章与多格式不削弱保护**：无论单章/多章、txt/epub/pdf，`DELETE /api/books/{id}` 只清上述 app 数据；原始文件在任何情况下不被触碰。生成失败重试、重新生成同样只读写 app 数据。
- **建议增加回归断言**：在删除相关单测中，断言 `original_path` 指向的文件在操作前后字节完全一致（size/mtime 不变）。

## 5. 待确认 / 风险

1. **epub 图片/脚注处理**：epub 正文常夹图片与脚注。策略建议——图片二进制不进入文本（仅可选保留 alt/图注文字），脚注按出现位置内联或忽略。需定调是否保留图注。
2. **pdf 扫描版（无文本层）**：`pypdf` 对扫描版无文本层会返回空/乱码。策略：检测提取文本为空或字数低于阈值时，标记该书为「不支持（扫描版）」并提示用户；**不**引入 OCR（避免重依赖），列入后续迭代。
3. **分章误判兜底**：模式匹配可能把「第一章 完」「作者有话说」误判为章。兜底：无章节→单章（CHP-002）；可选章节合并（CHP-011）；并在 UI 提供微调（P2）。需定调误判时的默认行为。
4. **一键脚本无浏览器环境降级**：纯服务器/SSH 无图形界面时，`xdg-open`/`open`/`start` 会失败。脚本需捕获失败、跳过打开、仅打印 `http://localhost:8000` 供用户自行访问，且**不因此中断已启动的服务**。
5. **存储约定变更**：章节化后音频路径由 `data/audio/<id>.mp3` 改为 `data/audio/<book_id>/<n>.mp3`，属对 ARCHITECTURE §7 共享约定的变更，需同步更新架构文档与既有单本音频端点（建议保留兼容或统一走章节接口）。
6. **依赖体积**：新增 `pypdf`、`beautifulsoup4`（及可选 `lxml`）会增加 venv 体积与首装时间，需评估首装时长是否在可接受范围。
